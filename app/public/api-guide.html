v-YuE2 VOS API

地址和身份

VOS 同源前缀 /app/com.ictrek.v-yue2；容器 http://v-yue2:8791，兼容别名 v-yue2-backend / v-yue2-frontend。没有独立宿主机映射端口。稳定端口是Go VOS网关，不是每个用户动态启动的Rust worker端口。侧栏 API 文档提供本页。

业务请求带 Authorization: Bearer $VOS_TOKEN，或先用该请求头 POST /vos/session 换取1小时HttpOnly/SameSite Strict的 v_yue2_session cookie。此POST不是传access_token的JSON接口；响应包含 sub、can_manage_models、accepted、revision。之后cookie仍按VOS userinfo核验，不是永久访问Key。写请求如有Origin必须匹配Host。

没有个人访问 API Key CRUD接口，V-Scheduler Key/厂商Key不能当作本应用管理身份。用户工作区按不可变sub隔离；模型准备要求 system_admin/platform_admin 或 com.ictrek.v-yue2:model:manage 权限。

许可和最小接入流程

首次运行必须明确同意当前模型许可。读取 POST /vos/session 返回的revision和accepted后，POST /vos/license JSON {revision:"RETURNED_REVISION",accepted:true} 保存本用户同意，成功200 {accepted:true}。不要在不了解许可时自动代用户勾选。GET /vos/about 返回当前应用/镜像等版本。容器根路径的 GET /health 是公开网关健康；通过VOS应用前缀的health会走用户身份和运行时流程，不能把两者当成同一就绪信号。

BASE=http://v-yue2:8791
curl -X POST "$BASE/vos/session" -H "Authorization: Bearer $VOS_TOKEN"
curl "$BASE/vos/about" -H "Authorization: Bearer $VOS_TOKEN"
# 用户同意许可后查看准备状态与模型能力
curl "$BASE/setup/status" -H "Authorization: Bearer $VOS_TOKEN"
curl "$BASE/v1/capabilities" -H "Authorization: Bearer $VOS_TOKEN"

Providers、模型与凭据修改

VOS的写作、封面、语音模型通过V-Scheduler发现和调用，并沿用当前VOS用户的模型可见性。GET /v1/provider/settings 返回配置状态（configured/provider），不是密钥值；/v1/provider/* 是VOS兼容映射。模型、上游、public/private和Key的新增修改在V-Scheduler进行。PUT/POST /v1/provider/settings 被403拒绝，旧 /v1/openrouter/* 返回410；不要根据桌面原生路由目录在VOS直接保存OpenRouter Key。

共享权重由V-Scheduler权重管理；/setup/download 和 /setup/cancel 要求模型管理权限，/setup/remove 返回409并要求到V-Scheduler处理共享权重。准备模型、安装文件、校准通过和可推理是不同状态；安装好仍可能等待执行器批准。普通用户不能通过下载接口删除其他用户共享权重。

音乐任务、资源与停止

POST /v1/music/jobs 输入CreateMusicJobRequest（完整字段在后文），例如 {style:"ambient piano",lyrics:"[Instrumental]",duration_seconds:30,seed:1234}。GET /v1/music/jobs 列活动任务，GET /v1/music/jobs/ended 列已结束任务；GET /v1/music/jobs/{job_id} 查询，POST同一路径取消，DELETE同一路径清理任务。不要把DELETE当作通用模型卸载接口。普通JSON返回原生对象，没有统一data包装。

MusicJob字段包括 id、client_ref?、submitted_at（Unix毫秒）、engine_id、status、dispatch、phase、style、lyrics、duration_seconds、generation_settings、song?、songs、message、playlist_id?等；可选字段可能省略。status为queued/running/completed/failed/cancelled；dispatch和phase描述排队/执行阶段，不是另一份最终结果。完成后从song/音乐库读取媒体，媒体接口返回原始音频/图片而不是JSON。

当前VOS的受管本地计算要求固定的YuE2 Q8权重组合及对应执行校准，缺绑定、文件、配置匹配或批准会503，不是“已下载就免预算”。忙时可能429；停止请求后网关等待原生进程停止和许可回执，不能仅凭断开HTTP判定资源已释放。中断/重启后终态任务保持私有，读取可以恢复；未知结果的POST不会被自动重放。

本应用当前支持任务头 X-VScheduler-Priority: background|interactive|high，默认background；请求许可时固定 preemptible=true、allow_preemption=false、force_admission=false，等待预算最多120秒。它没有把通用强制放行/抢占/等待头全部实现为任意可调参数，不能照搬其他应用的请求头说明。最终排队、预算及停止由调度器判定。

发现、绑定和校准 API

GET /api/v1/scheduler/discovery 返回非秘密scheduler元数据：protocol_version、app_id=com.ictrek.v-yue2、executor_base_url/upstream_url、binding_endpoint、execution_settings、sync_models、preemption_modes=[restart]。只有引擎和固定权重齐全才列 yue2-q8。GET binding返回 configured、binding_revision、approved_model_count，不回传凭证；这两个GET是网关早期只读元数据路径，不代表取得用户文件权限。

POST /api/v1/scheduler/binding 要求V-Scheduler VOS服务身份，不是普通管理员用户。请求字段 protocol_version=1、binding_revision（正整数）、app_id、url（固定controller地址）、token、executor_token、upstream_url、models（模型→executor）、model_limits、execution_settings。地址、当前引擎设置和执行器须严格匹配；JSON上限256KiB。非法422，活动执行/旧revision409，执行器验证失败503；同revision不能被当作随意覆盖配置的接口。应用自行维护注册/心跳/停止，不要求用户部署agent。

VOS和桌面接口的范围

VOS明确拒绝 /mcp*（403），不能用桌面MCP文档宣称安装后可直接连接VOS MCP。桌面引擎路径选择、任意网络暴露/本机保存、训练软件安装、VST、部分本地ASR/分离/MIDI等写操作也被网关拒绝；某些未校准本地操作503。后文完整Rust目录是原生参数查找参考，网关规则优先，列出不等于VOS放行。独立桌面自动化看仓库 MCP指南。

网关错误通常为 {error:string}；400输入、401VOS身份、403权限/桌面操作、409许可/共享权重或绑定冲突、410旧Provider地址、429资源忙、502worker不可达、503绑定/校准不可用。Rust原生错误及上传、SSE、二进制接口保留各自格式。库内容、取消、删除、覆写、模型安装须分别处理，200不是整条生成流程已完成。

v-YuE2 VOS API

Addresses and identity

VOS prefix: /app/com.ictrek.v-yue2; container: http://v-yue2:8791, with v-yue2-backend / v-yue2-frontend aliases. No independent host port is published. The stable address is the Go VOS gateway, not a per-user dynamic Rust-worker port. The sidebar API guide displays this reference.

Business requests use Authorization: Bearer $VOS_TOKEN, or POST /vos/session with that header to obtain a one-hour HttpOnly/SameSite Strict v_yue2_session cookie. This POST does not take access_token JSON. It returns sub, can_manage_models, accepted and revision. Cookie access still verifies VOS userinfo and is not a permanent API Key. A supplied Origin on writes must match Host.

There is no personal access-Key CRUD API. Scheduler/provider Keys are not gateway-management credentials. Workspaces are isolated by immutable sub. Model preparation requires system_admin/platform_admin or com.ictrek.v-yue2:model:manage permission.

Licenses and minimum integration

First use requires explicit consent to current model licenses. Inspect revision/accepted from POST /vos/session, then POST /vos/license with {revision:"RETURNED_REVISION",accepted:true} after the user agrees. Success200 {accepted:true}. Never silently accept for the user. GET /vos/about reports application/image versions. Container-root GET /health is public gateway health; health through the VOS app prefix follows user/runtime handling and is a different readiness signal.

BASE=http://v-yue2:8791
curl -X POST "$BASE/vos/session" -H "Authorization: Bearer $VOS_TOKEN"
curl "$BASE/vos/about" -H "Authorization: Bearer $VOS_TOKEN"
# After user consent, inspect preparation and capabilities.
curl "$BASE/setup/status" -H "Authorization: Bearer $VOS_TOKEN"
curl "$BASE/v1/capabilities" -H "Authorization: Bearer $VOS_TOKEN"

Providers, models and credential updates

VOS writing, cover and speech models are discovered/called through V-Scheduler as the current VOS user. GET /v1/provider/settings reports configured/provider status rather than a secret. /v1/provider/* is the VOS compatibility mapping. Add/change upstreams, model visibility and Keys in Scheduler. Writes to provider/settings are403; legacy /v1/openrouter/* is410. Native desktop routes do not permit storing OpenRouter credentials through VOS.

Shared weights are owned by Scheduler weight management. /setup/download and /setup/cancel require model-management permission; /setup/remove returns409 directing shared-weight changes to Scheduler. Preparation, downloaded files, calibration and inference readiness are distinct. Ordinary users cannot delete shared weights through a preparation call.

Music jobs, resources and cancellation

POST /v1/music/jobs accepts CreateMusicJobRequest, e.g. {style:"ambient piano",lyrics:"[Instrumental]",duration_seconds:30,seed:1234}. GET the collection for active jobs, GET /v1/music/jobs/ended for ended jobs, GET /v1/music/jobs/{job_id} for status, POST that path to cancel and DELETE to dismiss. DELETE is not general model unload. Native JSON objects have no universal data envelope.

MusicJob fields include id, optional client_ref, submitted_at (epoch milliseconds), engine_id, status, dispatch, phase, style, lyrics, duration_seconds, generation_settings, optional song, songs, message and optional playlist_id. Optional fields may be omitted. Status is queued/running/completed/failed/cancelled; dispatch and phase describe scheduling/execution rather than a separate final result. Completed song/library media routes return actual audio/images instead of JSON.

Managed local computation currently requires the fixed calibrated YuE2 Q8 combination. Missing binding/files/settings match/approval can yield503; downloading alone does not bypass admission. Busy resources can yield429. Cancellation waits for native stop evidence and permit handling; HTTP disconnection is not proof of resource release. Terminal records remain private across worker recycling; reads can recover, while an unknown-outcome POST is not automatically replayed.

The implemented task header is X-VScheduler-Priority: background/interactive/high, default background. Permit requests fix preemptible=true, allow_preemption=false and force_admission=false, with a120-second budget wait. This app does not expose every generic force/preemption/wait header as a user-adjustable option. Scheduler owns queueing, budgets and stop decisions.

Discovery, binding and calibration APIs

GET /api/v1/scheduler/discovery returns non-secret scheduler metadata: protocol_version, app_id=com.ictrek.v-yue2, executor_base_url/upstream_url, binding_endpoint, execution_settings, sync_models and preemption_modes=[restart]. Yue2-q8 is listed only when the engine and fixed weights are present. GET binding returns configured, binding_revision and approved_model_count without credentials. These early read-only metadata routes do not grant user-file access.

POST /api/v1/scheduler/binding requires the V-Scheduler VOS service identity, not an ordinary admin-user token. Fields: protocol_version=1, positive binding_revision, app_id, fixed controller url, token, executor_token, upstream_url, models (model→executor), model_limits and execution_settings. Addresses, current engine settings and approved executors must match. Body limit256KiB. Invalid422, active/stale binding409 and executor-verification failure503. The same revision is not an unrestricted replacement mechanism. Registration, heartbeats and stopping are application-managed, without user-deployed agents.

VOS versus desktop scope

VOS refuses /mcp* with403. Desktop MCP documentation does not make it a VOS MCP endpoint. Desktop executable selection, arbitrary network/local-save operations, training installation, VST and some local ASR/separation/MIDI writes are also refused; uncalibrated local operations can yield503. The Rust catalogue below is a parameter reference: gateway restrictions override catalogue presence. Standalone desktop automation is documented in the MCP guide.

Gateway errors commonly use {error:string}:400 input,401 VOS identity,403 permission/desktop-only,409 consent/shared-weight/binding conflict,410 retired Provider routes,429 capacity,502 unavailable worker and503 binding/calibration. Rust failures, uploads, SSE and binary endpoints retain their own formats. Distinguish cancellation, deletion, replacement and model installation. HTTP200 alone does not complete a generation workflow.
